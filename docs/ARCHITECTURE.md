# 实现结构

`src/sai_recorder` 是新增录制器，原有 `src/art_timelapse` 保留。新增模块复用上游 `sai.py` 的画布结构声明和已知版本指纹，其进程读写封装没有用于本录制器。

```text
中文 Tk / ttkbootstrap 面板
    ├─ 选择进程 / 画布、参数、完整预览、诊断与恢复
    └─ Recorder 会话控制
         ├─ 采集线程（按设置选择一个来源）
         │     SaiSource → CanvasReader → ReadOnlyProcess：全画布合成图
         │     SaiWindowSource ← Windows Graphics Capture：最后收到的 SAI2 窗口帧
         └─ 有界队列（最多 3 帧）→ 编码线程 → FFmpeg 子进程
               实时：时间戳映射为恒定帧率，缺采样时保持前一帧
               延时：每个保留采样写一帧
               MKV 分段 → 停止后无重编码合并为 MP4 / MKV
```

## 模块

| 文件 | 职责 |
| --- | --- |
| `memory.py` | 严格只读 Windows 进程访问、主模块地址、PE 数据区，短读即报错 |
| `source.py` | 指纹、适配缓存、已知 / 本机识别配置、画布链表和像素读取 |
| `window_source.py` | 按 SAI2 进程身份选择主窗口，异步采集窗口帧，监测窗口关闭、最小化和尺寸改变 |
| `config.py` | 参数验证、JSON 设置、等比尺寸、偶数像素补边 |
| `recording.py` | 单调时钟、暂停、定时采样、有界队列、状态、错误收尾 |
| `encoder.py` | FFmpeg 管道、软件 H.264、分段、合并和恢复 |
| `gui.py` | 中文 UI，工作线程和 UI 消息队列，录制期间锁定参数 |

会话状态为 `idle → starting → recording ↔ paused → finalizing → completed/error`。文件打开和编码等操作在后台，Tk 控件只在 UI 线程更新。停止会冻结有效时钟、结束采样、排空编码队列、关闭 FFmpeg 后合并；关闭窗口也走停止流程。

## 版本识别边界

`Profile` 包含程序 MD5、模块相对偏移和布局名。ASLR 后每次重取模块基址，进程身份同时比较 PID 和创建时间。开始录制时再确认程序指纹，目标画布比较地址和已知结构的 ID；尺寸改变后不继续沿用旧视频尺寸。

旧布局的 session 指针指向哨兵链表，跳过哨兵后是用户画布。识别只遍历 `.data/.bss` 内至多 16 MiB / 区的八字节对齐静态指针，尝试已知的两种布局；候选需要哨兵尺寸、用户画布名称 / 尺寸、全分辨率 tile map 以及首个像素块一致。用户画布链表最多遍历 256 个节点并检查循环。候选按根地址 / 布局去重，仅唯一候选可缓存。

2023.04.05（MD5 `9da34848ba9e6993a40262b462e0445d`）使用单独的专版配置。该文件的用户画布查找函数（RVA `0x1f140`）从模块相对地址 `0x319f30` 读取链尾，直接检查画布 ID（`+0x20`），再沿 `+0x10` 访问前一个用户画布，不跳过首节点。画布初始化（RVA `0x1e2d0`）中写入的 `+0x28` 分块合成图入口和尺寸字段也与读取配置对应。专版仅匹配这一份文件指纹，不加入通用扫描，仍需手动验证连接和成片。

完整采集先检查目标身份，读取 level 0 合成图，逐行批量读取 tile 指针，再逐块复制像素。帧末复查描述符以丢弃明显重建中的画面。没有进入 SAI 内部锁或设置钩子，因此不能保证每一帧所有分块来自完全相同的绘画更新时刻。6400 万像素限制同时约束异常尺寸和内存占用，但高分辨率 / 高帧率仍可能有较高开销。

窗口来源不读 level 0 图像来作录制帧。以选定 SAI2 进程的 PID 和创建时间验证身份，从所属可见主窗口中选择 HWND。采集回调转换 BGRA 为自有的 BGR 帧，仅持有最新帧；录制线程按会话采样节奏取帧。首次帧定义输出几何，后续窗口采集尺寸变化则结束会话。窗口来源只绑定窗口，不跟踪活动文档变化；选中的画布仍用于命名和归档。

## 时间与资源

实时模式使用暂停可扣除的 `time.monotonic` 时钟；采样时间戳映射到输出帧槽，跳采样不主动加速视频。停止时视频帧数取有效时长乘帧率向上取整，最少一帧。FFmpeg / 容器时间基和分段时间还需用户检查。

编码输入是 BGR24，输出使用 H.264 / yuv420p，编码线程最多四个 CPU 线程。队列拥塞时淘汰最旧的未编码采样，避免内存无限增长；不保证所有笔画中间态都能采到。写入连续阻塞超过十五秒时终止编码进程；FFmpeg 正常收尾最多等待三十秒，合并 / 单片恢复检查设有超时。

合并采用 concat demuxer 和 stream copy，不重复有损编码。正常导出和恢复都保留原分段；恢复逐段试解码，跳过坏片。分段容器、日志、清单和会话 JSON 存放在同一独立目录。一次异常不复用旧 Recorder 对象，下次录制新建会话。

`canvas_output.py` 用 `canvas.json` 标识可复用的画布目录。名称和像素尺寸仅用于排序建议，不能跨进程证明画布身份。`Recorder` 在此目录的 `_sessions/` 下创建独立会话；导出只在成功后将成片放到画布目录，用会话编号区分。旧版平铺目录仍按原位置恢复。

## 构建与交付

`tools/build_recorder.py` 使用 PyInstaller onedir，打包 windows-capture 扩展和 ttkbootstrap 资源。本机构建含 imageio-ffmpeg 提供的 Windows FFmpeg；GitHub 构建用 `--external-ffmpeg` 生成单独的外置包，不分发 FFmpeg，由用户安装。`build-info.json` 记录依赖版本、上游提交和未实测声明。随包提供依赖许可；GitHub Release 的源码由版本标签提供。

按用户要求，本次不执行 SAI 交互、录制性能测试或自动录制测试；打包成功仅说明构建工具完成，不能代替兼容性验收。
